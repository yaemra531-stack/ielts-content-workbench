# 雅思 AI 图文工作台：16 板块

打开 `index.html` 即可使用。沿用旧工作台的左右布局与配色，按用户 2026-09-20 的新要求拆为三个阶段、16 个独立板块。

## 使用

1. 左侧选当前板块；按独立字段填写，输入自动保存在当前浏览器。
2. 「请AI帮我处理这一步」生成包含已有内容的交接任务。复制到当前 Codex 对话处理，再将结果填回。
3. 点击「确认这一步已完成」后，主按钮变为「已完成，进入下一步 →」。下方始终说明下一步具体要做什么。
4. 第 13 步自动引用第 09 步标题/公式及第 12 步每图重点。过程图默认 AI 截图，其他默认真人实拍。按用户选定的方式，通过当前 Codex 对话生成真人实拍图的 A/B 参考图；上传对应图片后存入 IndexedDB，再完成实际拍摄勾选。网页没有独立生图 API，不会把提示词当成已生成图片。
5. 第 14 步开头引用第 10 步；正文其余六部分分别填写并显示字数。
6. 第 16 步随时可导出 Markdown 草稿；前 15 步完成且没有待复核项时导出成品。文件名为本地日期＋一句话概述关键词，草稿加「-草稿」后缀。

同一篇允许多个板块并行推进，编号仅作方法导航。修改本板块后重新确认本板块；仅关联板块提示「待复核」，无关板块的完成进度不受影响，所有文字和六轮勾选均保留。标题/图片重点/风格变化时，关联参考图仍会提示需更新。AI 交接包含所有板块的当前内容，不再只包含编号靠前的内容。

步骤状态包括：未开始、进行中、待复核、已完成。进度只计已完成且无待复核标记的板块；草稿下载不代表第 16 步成品完成。系统不会自动并发启动多个 AI 任务。

## 保存与边界

- 文本、选择、勾选保存到浏览器 localStorage；A/B 参考图保存到 IndexedDB。浏览器存储不是云同步，删除浏览器数据会丢失记录。
- 导出的 Markdown 包含 01—15 全部文本、选项、检查项和参考图文件名，不包含图片二进制；请另外保留图片原文件。
- 若在原浏览器、原地址打开，可读取旧六步版保存的记录，展示在「六步版旧记录」中并包含在导出内容里；不擅自拆分或标记旧记录为新步骤已完成。
- 旧页面及源保留为 `six-step-backup.html` 和 `six-step-source-backup.html`。`workbench-source.html` 是旧导出源；当前入口为 `index.html`，逻辑在 `app.js`，样式在 `app.css`。
- 当前支持多篇本地笔记，未部署在线站点。内联旧原型不会自动与此网页同步。

## 验证

`test-workbench.cjs` 用隔离浏览器检查 16 板块、必填与字数、完成按钮切换、跨步引用、图片导入/刷新恢复/失效标记、Markdown 内容与文件名、全流程进度、移动布局，以及六步版旧记录保留。

`test-parallel.cjs` 检查乱序完成、多个板块同时保留草稿、无关进度保留、关联复核、六轮勾选不清空、完整上下文交接与草稿导出。

## 多篇笔记与备份（2026-09-20）

- 左侧显示最后成功保存的本地时间；每次输入即时保存。关闭后在同一 Chrome 用户配置、同一路径打开即可继续。图片上传期间显示保存中。
- “新建笔记”保留原篇，默认复制 01—03 的文字（可取消），其余板块从空白开始；不继承完成勾选。通过“我的笔记”切换，每篇保留独立进度和当前板块。
- 原单篇 v3 数据首次使用自动读入新笔记库，原存储键保留不删。新笔记库保存在 `ielts-content-workbench-library-v1`。
- “备份全部笔记”下载 JSON，包含所有笔记的文字、进度以及已上传的参考图二进制内容。Markdown 仍用于阅读和成品输出，不能用于完整恢复。
- “恢复备份”验证文件后添加带“（恢复）”后缀的独立副本，不覆盖现有笔记；参考图分配新的素材 ID。重复恢复会添加更多副本。
- 本机保存不是云同步。备份按钮需手动点击，下载的文件请另行保管。更换浏览器/电脑可用完整备份恢复。
- 若存储空间不足或另一窗口已修改笔记库，会显示保存失败并阻止新建/切换造成内容丢失；应先备份当前内容再刷新。
- `test-library.cjs` 覆盖迁移、时间显示、关闭重开、多笔记隔离、账号设定沿用、含图片备份跨配置恢复、损坏文件拒绝、存储失败及手机布局。

## 继续填写与起步提示

- 系统自动恢复每篇上次所在板块；左侧可选填“下次从这里继续”，提醒绑定填写时所在板块，可一键返回。提醒按篇独立保存，并包含在完整 JSON 备份中。新建篇不沿用旧提醒。
- 每步显示对应的常见卡点与最低完成标准，原来的验证要求与自由切换流程保持不变。

## 稳定版 V1：代码更新与数据备份

本目录作为独立 Git 仓库管理。桌面入口和工作台文件位置不变。

### 代码更新

首次准备开发环境（需要 Node.js 和 npm）：

```sh
npm ci
npx playwright install chromium
npm test
```

修改后执行：

```sh
npm run sync -- "说明本次改动"
```

该命令先测试，再提交明确允许的程序文件，最后推送私有仓库。无需为了日常填写运行此命令。每次推送还会触发 GitHub Actions 检查。提交成功但上传失败时，本地提交仍保留，恢复连接后重试即可；不要强制推送。

Git 只管理程序；旧原型、个人桌面启动器及备份文件留在本机并被排除。改版前建议先从界面下载完整备份。回退程序前也先备份，旧程序未必理解新数据结构。

### 数据保管

- 每天收工或完成一篇后，手动点“备份全部笔记”，把下载的 JSON 放到自己固定的备份目录。可另留一份在自己的云盘或备份硬盘。
- 目前没有后台定时备份、自动云同步或双向合并。代码上传不会上传笔记。
- 本地版作为主记录。将备份导入另一浏览器/网站时会添加恢复副本；反复导入会重复，不适合作为双端同时编辑的同步机制。
- 若将来确实需要多端接续，再加入带版本判断与冲突处理的数据同步。

### 将来使用 GitHub Pages

目前保持私有仓库、不开启 Pages。启用前确认私有仓库的套餐支持和站点访问权限：私有仓库不等于发布出的站点私有。

页面没有构建依赖。发布时仅打包 `index.html`、`app.js`、`app.css`（可选带图标），不打包整个目录。线上首次使用需从本地导出完整备份再恢复；各站点/浏览器的数据不自动共享。不会因上线而自动调用 AI 或生图服务。
